# Awards, Commendations, and Performance Reviews

## Purpose

This is the application-safe praise evidence layer for Troy J. Hokanson. It connects verified
awards, performance-review language, written commendations, and stakeholder feedback to the
specific experience each item corroborates.

Raw personnel records, reviewer names, protected case identifiers, and private source links do
not belong in this public file.

Use this file after the job requirement-to-evidence matrix is built. Select the experience first,
then use praise only when it adds independent proof of a required quality.

---

## Evidence Labels

| Label | Meaning | Application rule |
|---|---|---|
| `verified_verbatim` | Exact wording confirmed in a source document | May appear in quotation marks |
| `verified_excerpt` | Exact, shortened passage confirmed in a source document | May appear in quotation marks without changing words |
| `verified_paraphrase` | Meaning is verified, but wording is summarized | Never place in quotation marks |
| `pending_source` | Source exists or is referenced but has not been rechecked | Do not use externally |

Reviewer attribution must be role-only, such as `a supervisor`, `an outside-agency leader`,
`a business owner`, or `a performance review`. Do not identify the reviewer by name.

---

## Selection Rules

1. Match the job's high-value requirement to a verified experience in `CASE_BANK.md`,
   `CAREER_CONSTANTS.md`, or another approved repository source.
2. Search the crosswalk below for praise tied to that experience or competency.
3. Rank candidates by direct relevance, proof strength, specificity, distinctiveness, recency,
   and whether the item adds a point not already made elsewhere.
4. Prefer praise that verifies how Troy worked: initiative, judgment, follow-through,
   collaboration, technical translation, customer confidence, or defensible case preparation.
5. Do not use praise as a substitute for the underlying experience or outcome.
6. Resumes and CVs use no direct praise quotations. Summarize the verified recognition.
7. A cover letter normally uses zero or one direct quotation. A second is allowed only when it
   comes from a different source type and adds a distinct, role-critical point.
8. Interview preparation and recruiter packets may use more excerpts, but each must remain tied
   to a verified experience and privacy-safe context.
9. Do not stack generic praise. One specific corroborating item is stronger than several broad
   statements about hard work.
10. If the exact wording cannot be confirmed, use a labeled paraphrase or omit the item.

## Job-to-Praise Query Method

For each top job requirement, use this sequence:

1. **Requirement:** What outcome or behavior is the employer buying?
2. **Experience:** Which verified case, assignment, program, teaching example, or implementation
   proves Troy did comparable work?
3. **Praise:** Which crosswalk item independently corroborates how he performed that work?
4. **Use decision:** Does the praise add proof, or merely repeat the experience?
5. **Format decision:** Resume summary, cover-letter quote, interview support, or omit.
6. **Privacy check:** Quote status verified; reviewer name suppressed; identifiers removed.
7. **Duplication check:** Do not use the same experience in the summary, resume, cover letter,
   and interview opener unless the role truly turns on that one example.

Suggested ranking formula:

`relevance (0-5) + proof strength (0-5) + specificity (0-3) + distinctiveness (0-3) + recency (0-2) - duplication/privacy risk (0-4)`

Use the score to compare eligible items, not to make an unverified item usable.

5. Add only the best application-safe item to this crosswalk.

7. Update Notion with the source status and any unresolved crosswalk.
8. Re-run privacy, factual, and quote-integrity checks before use.
