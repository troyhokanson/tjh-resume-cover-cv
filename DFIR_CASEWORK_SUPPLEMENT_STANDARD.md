# DFIR Casework Supplement Standard

Effective September 20, 2026. Standing instruction from Troy.

## Required inclusion

Automatically prepare a tailored, one-page **Selected Digital Forensics Casework** supplement for every relevant DFIR application. Do not ask Troy whether to add it each time.

Apply when the actual posting materially values forensic acquisition, device or provider-records analysis, digital evidence, forensic reporting, or examination support. This includes digital forensic examiner/investigator roles and relevant corporate, eDiscovery, incident-response, or forensic-vendor roles where Troy's verified examination work provides meaningful evidence. A DFIR keyword alone is insufficient; record the applicability decision and rationale. Do not imply unverified enterprise incident-response, cloud-security, scripting, or network-forensics experience.

## Content

- Select three concise, role-relevant examples explaining Troy's own role, the evidence or examination methods, and the work product delivered. Use fewer only when the available verified evidence warrants it; record the reason.
- Add useful detail beyond the resume and cover letter rather than another general skills inventory.
- Prefer recent documented work when equally relevant. Distinguish case dates, examination dates, and later court outcomes. Never relabel older work as recent.
- Consider device examinations, Google/Facebook/Snapchat provider-records analysis, lawful preservation and collection, artifact correlation, timelines, focused reports, screenshots, investigator support, and prosecution preparation when supported by evidence.
- Select verified commendations or performance-review recognition that corroborate the chosen work. Do not attach praise or an outcome to an unrelated case.
- Use current repository evidence and primary records. Record user-confirmed additions separately in private provenance. Do not infer tools, artifact findings, quantities, outcomes, or lead-investigator status from a case-log entry alone.
- Preserve all privacy and evidence restrictions. Exclude names of subjects, victims and reviewers, protected case identifiers, account/device identifiers, private addresses, and restricted investigative details. Do not include raw evidence screenshots.
- Describe historical tools accurately. Prefer the relevant method and work product over an obsolete product name when the name adds no value. Never substitute a newer tool that Troy did not use.

## Production and validation

Produce a separate PDF, editable DOCX, and Markdown source under the application naming convention, using the suffix `Digital_Forensics_Casework`. Keep the resume and cover letter separate.

Use the locked full-bleed navy/gold header and Garamond typography. Follow the current design, contact, privacy, voice, and formatting-delivery standards. One page is required: edit repetitive content before reducing type or spacing, and never breach typography minimums.

Run applicable factual, privacy, language, contact, header, and body checks; verify selectable text, reading order, one-page length, and every rendered page visually. Bind the review to final file hashes. A passed generic validator does not itself establish the one-page requirement or factual accuracy.

Save the source, DOCX, PDF, and validation records with the application packet in authorized destinations. Track applicability, completion, file links, validation, and any exception in application metadata and Notion. An applicable packet is document-complete only when this supplement passes its checks, unless Troy explicitly waives it or employer instructions prohibit it.

## Upload and authorization

Prepare the page automatically, but include it in an actual submission only when employer instructions and attachment fields permit supplemental material. If prohibited or unsupported, retain it for interviews and record that it was not uploaded. Do not append it to the resume or bypass an attachment/page limit to force inclusion.

This rule authorizes routine preparation, not application submission, sending, public publication, or changes to file sharing. Existing approval requirements remain in force.
