# Weekly Evidence-System Diagnostic Standard

This standard defines the minimum weekly diagnostic for career evidence and
career-material systems. It is intentionally metadata- and exception-first. It
does not authorize public release of private source material.

## System authority

- Google Drive controls private evidence and final private files.
- Notion controls structured working indexes, application status, next actions,
  and cross-system receipts.
- GitHub controls reusable standards, validation logic, and approved public-safe
  wording.
- Microsoft OneDrive and SharePoint are independently audited storage surfaces.
  A personal OneDrive connection does not prove that an organizational
  SharePoint site was checked.
- NotebookLM and other analysis tools are non-authoritative until an output is
  verified against original sources and deliberately promoted.

## Required weekly sequence

1. Inventory every configured local or synced root using metadata only.
2. Record missing, timed-out, and truncated roots as exceptions, never as clean
   scans.
3. Review the intake folder before the canonical evidence folders.
4. Review cases, court outcomes, training, certifications, and awards before
   lower-priority supporting folders.
5. Identify duplicate candidates by normalized name and size, then verify exact
   identity with SHA-256, native revision history, or source comparison.
6. Keep the designated canonical source in place. Move only verified extra
   copies to a dated quarantine; do not delete them during the weekly pass.
7. Compare Drive holdings with the matching Notion databases. Create or update
   a record only when source identity, category, and privacy status are grounded.
8. Record exactly which Microsoft drives, sites, libraries, and folders were
   reachable.
9. Audit GitHub for role-family, evidence, privacy, and workflow consistency.
10. Write a cross-system receipt and verify every write by reading it back.

## Duplicate dispositions

| Finding | Default disposition |
|---|---|
| Same name and SHA-256 | Retain authority; quarantine extra copies |
| Same name and size only | Candidate only; compare content before moving |
| Same subject with different content | Preserve both and document provenance |
| Drive source without Notion record | Queue for evidence-grounded indexing |
| Notion record without a Drive source | Mark a source gap; do not call it verified |
| Private source referenced by GitHub | Replace with approved sanitized wording |
| Connector write without read-back | Treat the update as incomplete |

## Privacy and release controls

Do not commit raw evidence, private identifiers, health information, internal
case numbers, or unsanitized filenames. Public-facing material must satisfy the
repository privacy standard and remain useful across the canonical career role
families, including public-safety customer success, solutions and pre-sales,
implementation and professional services, project and program delivery, Trust
and Safety, corporate security, intelligence and DFIR, and financial-crimes or
SIU work.

## Minimum receipt

The weekly receipt must identify:

- scan time and exact systems and roots covered;
- complete, missing, timed-out, and truncated scopes;
- verified duplicates quarantined and canonical sources retained;
- Notion database counts and source-link gaps;
- Microsoft drives and SharePoint sites actually reached;
- GitHub repositories and standards checked;
- writes made and their read-back status; and
- unresolved conflicts, next evidence targets, and required human decisions.
