# Cross-Source File Inventory and Migration Standard

## Purpose

This standard governs discovery, comparison, transfer, registration, and retention of private career-evidence files stored across cloud providers.

The goal is to identify net-new or materially stronger evidence without creating duplicate records, losing provenance, exposing protected information, or treating connector coverage as complete when it is not.

## System Ownership

- **Google Drive:** authoritative private evidence locker, canonical source files, hashes, duplicate groups, retention decisions, and the Career Evidence Master.
- **Notion:** human-readable command center, migration status, review queue, exceptions, transfer receipts, and next actions.
- **GitHub:** generic standards, reusable validation logic, manifest tooling, and privacy-safe workflow rules only.
- **Source providers:** discovery and retrieval locations. They are not authoritative after a verified canonical copy is registered in Google Drive.

Never store case numbers, subject names, victim information, protected identifiers, private evidence, or raw manifests containing sensitive paths in this public repository.

## Inventory Coverage Rules

1. Record the connected account identity and provider.
2. Use provider-native recursive listing and pagination when available.
3. Continue pagination until the provider reports no more results before claiming completeness.
4. When a provider does not expose recursive listing, record the exact limitation and use the best available fallback channels, such as:
   - recent-file listings;
   - connected-source search;
   - exact file links;
   - exported provider manifests;
   - a local sync-folder manifest generated by the reconciliation utility.
5. Never describe a partial recent-file list or keyword search as a full inventory.
6. A provider remains `Partial Coverage` until either recursive enumeration is completed or an exported/local manifest is reconciled.

## Candidate Classification

Every discovered file must receive one of these statuses:

- **Exact Duplicate:** same cryptographic hash as a registered or canonical file.
- **Probable Duplicate:** normalized filename and size match, but no cryptographic hash is available.
- **Name Conflict:** normalized filename matches while size or hash differs.
- **Derivative:** content is a later summary, redaction, export, conversion, or reformatted copy of another source.
- **Net-New Evidence:** no reliable duplicate match and the file adds source-supported information.
- **Stronger Replacement Candidate:** the file is more authoritative, complete, legible, or original than an existing derivative.
- **Quarantine:** filename/content mismatch, corruption, privacy risk, unsupported role claim, or uncertain provenance.
- **Out of Scope:** no meaningful case, training, certification, award, assignment, education, application, or career-evidence value.

## Evidence-Value Scoring

Score each candidate from 1 to 100 using source quality and incremental value, not sensational content.

Suggested factors:

- **Authority, 0-25:** official court record, contemporaneous report, signed warrant, certificate, transcript, or original workbook.
- **Incremental information, 0-25:** adds a new role, date, method, outcome, metric, course, credential, award, or assignment.
- **Career relevance, 0-20:** supports an approved career lane, verified accomplishment, STAR example, resume bullet, or interview preparation.
- **Verification utility, 0-15:** resolves a conflict, crosswalk, duplicate, chronology gap, or role ambiguity.
- **Durability, 0-10:** original file, readable, hashable, and suitable for long-term retention.
- **Privacy usability, 0-5:** can support sanitized internal drafting without unnecessary exposure.

Deduct for derivative-only content, unsupported assertions, content mismatch, unresolved identity, duplicate evidence, or unusable privacy risk.

## Transfer Rules

1. Compare the candidate against Google Drive before transfer.
2. Prefer the original file type and preserve the original filename unless the filename is misleading or malformed.
3. Do not overwrite an existing canonical file unless the user explicitly approves replacement and the replacement is verified.
4. Upload net-new evidence to the appropriate private Google Drive folder.
5. Preserve the source provider, original path or item URL, file size, modified time, and available hash.
6. Hash the transferred file when possible.
7. Register the file in the Career Evidence Master and read back the written row.
8. Link the file to the correct case, ECTF record, training record, certification, award, assignment, or data-quality exception.
9. Do not delete the source-provider copy as part of routine migration.

## Privacy and Public-Use Rules

- Source files remain private unless separately approved for release.
- BCA application responses and similar self-authored selection materials are internal reference sources only and may not be used as public proof.
- Public-facing claims must be independently supported by approved evidence under the Case Evidence Review Standard.
- Protected case identifiers, victim information, personnel identifiers, addresses, account data, device identifiers, and raw evidence paths remain private.

## Exception Handling

When a connector or provider blocks complete enumeration:

1. Record the provider, account, attempted method, error or limitation, and date.
2. Continue with every independent source that remains accessible.
3. Create a manifest-generation action for the blocked source.
4. Do not mark the inventory complete until the manifest is imported and reconciled.
5. Report partial completion accurately rather than estimating unseen files.

## Completion Gate

A cross-source migration batch is complete only when:

- provider coverage is classified as complete or explicitly partial;
- every discovered high-value candidate is classified;
- duplicate and conflict decisions are recorded;
- every approved transfer is confirmed in Google Drive;
- every transferred source is registered and read back;
- Notion contains the migration receipt, exceptions, and next actions;
- GitHub contains only privacy-safe standards and tooling;
- no source file was deleted without explicit approval;
- a final value-added score and evidence-based explanation are reported.
